# Re-score: Rick and Dana after the 2026-10-22 fix window

**This is a simulated walkthrough.** I performed every step in the real app (browser mode: bridge and Vite, against the
bundled practice-board simulator, no hardware), scripted with Playwright, so the clicks and screen text below are
measured. The personas, what they say and their SUS answers are an informed guess, not data from real users. The baseline
is the usability evaluation of 2026-10-21 (Rick 20.0, Dana 40.0). Earlier rounds that day had already fixed Stop,
beginner settings, confirmations, contrast, bundled guides, visible shows, the activity log and library rename/delete.
This re-score covers the app at the end of the window. Screenshots are in [`2026-10-22-rescore/`](2026-10-22-rescore/).

Note on the screenshots: in browser development mode the repository's example plugins load. That adds the "Board list
(example plugin)" tab and a one-time consent dialog for the example "Demo lamps" adapter, which I dismissed with "Not
now". The desktop app does not load them.

## Rick (set builder, PicoBoo user, low tech comfort)

**Task: make the porch prop's fog come on for 5 seconds when the mat is stepped on, and try it.**

- Before: he would not attempt it. The path was Your library → New effect → an editor with two code panes and 7 buttons
  → "Try it on a practice board" → scroll to a panel at the bottom → then pick the real board from a list to send it.
- Now (clicks measured from the Boards page; time estimated): **6 clicks plus typing a name, about 1 minute.**
  1. Open the board.
  2. **Make it do something…** ([04](2026-10-22-rescore/04-rick-board-page.png)).
  3. A dialog titled "What should Practice board 1 do?" ([05](2026-10-22-rescore/05-rick-what-should-it-do.png)): type a
     name, open "Turn on".
  4. Pick "RLY1 (relay: fog machines, mains gear)".
  5. **Make it and send it to Practice board 1**.
  6. Hold **Press** on TRIG1, as the blue line says: "Try it now: hold Press on TRIG1 below for a moment. RLY1 turns on
     for 5 seconds." ([06](2026-10-22-rescore/06-rick-try-it-now.png)). RLY1 goes on, then off
     ([07](2026-10-22-rescore/07-rick-fog-on.png)).
- Stop: the red Stop turns everything off. TRIG1's tile now reads "Ignored: the board is stopped"
  ([08](2026-10-22-rescore/08-rick-stopped.png)).
- Never lose work: he typed a note in the effect, went to Boards and came back. The note was still there, with "Your
  changes here are not saved yet. Press Save to keep them." ([09](2026-10-22-rescore/09-rick-unsaved-kept.png)).
- His input tiles now name the on-board record buttons ("Record button: hold it to record on the board", "Record mode:
  picks the output to record"). That is the PicoBoo-style path he knows, now visible in Studio.
- First run says "Not sure? Press Use this folder…" ([01](2026-10-22-rescore/01-rick-welcome.png)).

What still trips him:
- He still has to know what RLY1 is. The dialog's hint ("Fog machines usually go on RLY1") helps.
- There are still three ways to program.
- The library editor is still two code panes. He only meets it if he goes looking.

## Dana (Christmas light show, never coded)

**Task: a lamp-and-fog effect from scratch.**

- Before: she failed unaided. "lamp = on" gave "there is no lamp on this board…", and naming OUT1 "lamp" did not help.
- Now:
  - The same lines get a plain line under each message ([10](2026-10-22-rescore/10-dana-no-lamp-hint-generic.png)):
    - "Lights usually go on out1 to out4 (they can dim). If yours is on OUT1, write out1."
    - "Fog machines, air blasters, motors and mains gear usually go on a relay. If yours is on RLY1, write rly1."
  - After she names OUT1 "lamp" and RLY1 "fog" in the board's Settings, the names show on the tiles at once
    ([11](2026-10-22-rescore/11-dana-labels-on-tiles.png)).
  - Checked with that board's settings, the hint says ([13](2026-10-22-rescore/13-dana-hint-board-names.png)):
    - "Your lamp is on OUT1: write out1 instead of lamp."
    - "Your fog is on RLY1: write rly1 instead of fog."
  - She fixed both lines as told, got "Looks good", and tried it on the practice board.
- She went to the board and back mid-edit. Her unfinished text was kept, with the "not saved yet" note
  ([12](2026-10-22-rescore/12-dana-unsaved-note.png)).
- The practice board's plot shows only TRIG1 and the two outputs that moved, with "30 s ago … now" along the bottom
  ([14](2026-10-22-rescore/14-dana-practice-plot.png)).
- Unaided success in the editor: **yes, about 8 minutes (estimate)** (was a fail, or about 20 minutes copying an example).
- The shorter route, with no code at all, is on the board page. "Make it do something…" → Turn on "OUT1: lamp" → And also
  turn on "RLY1: fog" → Make it and send it ([17](2026-10-22-rescore/17-dana-lamp-and-fog-choices.png)). The menus show
  her own names. The line above the tiles says "OUT1 (lamp) and RLY1 (fog) turn on for 5 seconds". Pressing TRIG1 turns
  both on ([18](2026-10-22-rescore/18-dana-lamp-and-fog-on.png)). That is 7 clicks plus a name, about 1 minute (estimate).
- Wiring guides: Help has them ([16](2026-10-22-rescore/16-dana-help-guides.png)); every tile has "How do I wire this?".
- Still open for her:
  - Firmware updates still need "Check for firmware updates: set it up" ([15](2026-10-22-rescore/15-dana-boards-firmware-setup-link.png)),
    and she does not know what a release list is.
  - ~~The board-supplied "Save now" button is unexplained.~~ Fixed: a plain line under it says what it does.
  - The board's checker still does not accept "lamp" itself (a firmware change).

## What remains (ranked for first-time non-programmers)

1. Scripts should accept the names people gave outputs (`lamp = on`). This is a firmware checker change; the hint is a
   stopgap.
2. Firmware update source: ship an official release address with the desktop build, so the setup step disappears.
3. "Make it do something…" covers one input and up to two outputs for one stretch of time. Anything longer (a fade, a
   second step) still means the editor.
4. Phone page (#14): tabs off-screen at 390 px, Record defaulting to the example show, the show editor in ms. These are
   firmware web UI items.
5. ~~Board-supplied actions such as "Save now" need a one-line explanation from the board.~~ Fixed in Studio (a
   known line for `save`, or the board's own `help`).
6. ~~Blank lines appear as empty "#" blocks in the blocks view.~~ Fixed: blank lines get no block.
7. ~~In development browser mode, the example plugins (a tab and a consent dialog that mentions MQTT) show to beginners.~~
   Fixed: only with `SPECTER_STUDIO_EXAMPLE_PLUGINS=1`.
